# Phase 4: UI/UX 설계

## 상태
- [x] 설계 완료 (2026-03-30, /plan-design-review)

## 설계 원칙
1. **APP UI 분류**: 워크스페이스 중심, 데이터 밀도 높음, 태스크 중심
2. **차분한 표면**: 강한 타이포, 적은 색상, 유틸리티 언어
3. **빈 상태는 기능**: "없습니다"로 끝나지 않고 항상 다음 행동 안내
4. **중복 실행 방지**: 트랜잭션 버튼은 클릭 즉시 비활성화
5. **PC 우선**: 데스크톱 최적화, 핵심 화면만 모바일 반응형

## 화면별 정보 계층

### 대시보드
```
1순위: 재발주 필요 품목 알람 (min_stock_qty 이하)
       → 없으면 "모든 재고 정상" 녹색 배너
       → 있으면 품목 리스트 + "PO 생성" 바로가기
2순위: 처리 대기 건수
       - draft PO 수, draft SO 수, 미처리 입고 수
3순위: 이번 달 매입/매출 요약 (총액)
```

**온보딩 위젯** (기초 데이터 0건일 때):
```
기초 데이터 설정

거래처    ─────  0건    [등록]
──────────────────────────────
창고      ─────  0건    [등록]
──────────────────────────────
품목      ─────  0건    [등록]

- 체크 아이콘 대신 수평 구분선 + 건수 표시 (산업 정밀 스타일)
- 완료된 항목은 건수가 Success 색상(#2B7A6F)으로 변경
- 완료된 항목의 [등록] 버튼은 숨김
- 모두 완료되면 위젯 자동 사라짐
```

### 품목 리스트
```
1순위: 품목코드 + 품목명 + 현재 총 재고량 (inventory_summary JOIN)
2순위: 유형 뱃지 (basic/assembly), 단위, 카테고리
3순위: 최소재고 대비 경고 (재고 < min_stock_qty → 경고 아이콘)
```
- assembly 품목에는 조립 아이콘 표시
- 검색: 코드/이름 통합 검색
- 필터: 카테고리, 유형(basic/assembly), 활성상태

### 품목 상세 → BOM 탭
- 품목 상세 화면의 탭: 기본정보 | BOM | 재고현황 | 거래이력
- BOM 탭: assembly 품목일 때만 활성
  - 재료 목록 테이블 (재료 품목, 수량)
  - 인라인 편집으로 재료 추가/삭제

### PO 목록
```
1순위: PO번호, 공급업체명, 상태 배지
2순위: 총 금액, 입고율(%), 지급율(%)
3순위: 발주일, 예상입고일
```

### PO 상세 (통합 뷰)
```
[헤더] PO번호, 공급업체, 상태, 발주일/예상입고일
[탭: 발주내역 | 입고이력 | 지급이력]

발주내역 탭:
  - 라인 테이블 (품목, 수량, 단가, 금액, 입고진행률)
  - [입고 처리] 버튼 → /goods-receipts/new?po=[id]

입고이력 탭:
  - 입고 건별 목록 (입고일, 입고번호, 품목별 수량)

지급이력 탭:
  - 지급 건별 목록 (지급일, 금액, 방법)
  - 총 금액 vs 누적 지급 vs 잔액 표시
  - [지급 등록] 버튼
```

### 조립 지시 생성
```
1. BOM 선택 (product_item + BOM 버전)
2. 조립 수량 입력
3. 재료 가용성 사전 확인 테이블:
   ┌──────────┬──────────┬──────────┬──────────┬────────┐
   │ 재료 품목 │ 필요 수량 │ 현재고    │ 가용 여부 │ 부족량  │
   ├──────────┼──────────┼──────────┼──────────┼────────┤
   │ A        │ 50       │ 80       │ ✅ 충분  │ -      │
   │ B        │ 100      │ 60       │ ❌ 부족  │ 40     │
   └──────────┴──────────┴──────────┴──────────┴────────┘
4. 예상 원가 미리보기 (FIFO 기준 계산):
   ┌────────────────────────────────────────┐
   │ 예상 조립 원가                          │
   │ 총 예상 원가: ₩2,000    단위 원가: ₩40  │
   │ (FIFO 기준, 실제 원가는 실행 시 확정)    │
   └────────────────────────────────────────┘
   - inventory_lots에서 FIFO 순서로 lot별 unit_cost * 소비량 합산
   - useMaterialAvailability 훅을 확장하여 lot 단가 정보 포함
   - 모든 재료 충분할 때만 예상 원가 표시
   - 재료 부족 시 "재료 충분 시 원가 계산 가능" 안내
5. [조립 실행] 버튼 → 재료 부족 시 비활성화
```

### 조립 완료 화면 (조립 상세)
```
✅ 조립 완료
품목: C, 수량: 50개
총 원가: ₩2,000, 단위원가: ₩40
재료 소비 내역:
  A: 50개 소비 (로트 3개에서 FIFO 소비)
  B: 100개 소비 (로트 2개에서 FIFO 소비)

[목록으로]  [재고 현황 확인 →]  [동일 품목 재조립 →]
```
- "재고 현황 확인": `/inventory`로 이동 (결과 품목 재고 확인)
- "동일 품목 재조립": `/assembly-orders/new`로 이동, product_item_id와 bom_header_id 쿼리 파라미터로 사전 선택

## 상태별 UI 명세

### 상태 색상 토큰
| 상태 | 색상 | shadcn variant |
|------|------|----------------|
| draft | gray | `secondary` |
| confirmed | #4A7B94 (Info 청회색) | `default` (커스텀) |
| partially_received | amber | `warning` (커스텀) |
| completed/received | green | `success` (커스텀) |
| shipped | green | `success` (커스텀) |
| cancelled | red | `destructive` |

### 공통 상태 규칙

**Loading:**
- 목록: 테이블 스켈레톤 (헤더 유지, 행만 스켈레톤)
- 트랜잭션 실행: 버튼 비활성화 + 스피너 + "처리 중..." 텍스트
- 필터 변경: 이전 데이터 유지하며 페이드 교체

**Empty:**
- 모든 빈 상태에 CTA 버튼 포함
- 대시보드: 온보딩 체크리스트 위젯
- 목록: "[항목]이 없습니다. [첫 항목 등록하기]" + 등록 버튼

**Error:**
- DB RAISE EXCEPTION → 한국어 에러 메시지로 파싱
- 재고 부족: 품목명 + 필요수량 + 현재고 + 부족량 형식
- 네트워크 에러: 상단 배너 "연결이 불안정합니다. 자동 재연결 중..."
- 폼 에러: 필드별 인라인 에러 메시지 (Zod 검증)

**Success:**
- 토스트 메시지에 결과 수치 포함
- 입고: "3개 품목 입고 완료, 로트 3개 생성"
- 조립: "C 50개 조립 완료, 단위원가 ₩40"
- 성공 후 복귀 흐름:
  - 입고 완료 → PO 상세로 자동 이동 (2초 후, 입고율 업데이트 확인)
  - 조립 완료 → 조립 상세로 자동 이동 (원가 내역 확인)
  - 출고 완료 → SO 상세로 자동 이동
  - 일반 CRUD → 상세 화면으로 자동 이동 (2초 후)

**Partial:**
- PO 부분입고: 상태 배지 amber + 입고율 프로그레스 바
- PO 분할지급: 지급율 프로그레스 바 (지급탭 헤더)

### 슬라이스 3~5 상태 커버리지

**조립 지시 (assembly_orders):**

| FEATURE | LOADING | EMPTY | ERROR | SUCCESS | PARTIAL |
|---------|---------|-------|-------|---------|---------|
| 조립 목록 | 테이블 스켈레톤 | "조립 이력이 없습니다" + [조립 생성] CTA | - | - | - |
| BOM 선택 | 스피너 | "조립 가능 품목 없음" + [품목에 BOM 등록] 링크 | - | - | - |
| 재료 가용성 확인 | 스켈레톤 | - | "재고 조회 실패" + 재시도 | ✅ 모든 재료 충분 | ⚠️ 일부 재료 부족 (부족량 표시) |
| 조립 실행 | 버튼 비활성화 + "처리 중..." | - | 에러 토스트 + 폼 데이터 유지 (아래 상세) | 완료 화면 (원가 내역) | - |

**조립 실행 에러 복구:**
- 실패 시 폼 데이터(품목, BOM, 수량, 창고) 그대로 유지 — 페이지 이동 없음
- 에러 토스트에 구체적 사유 표시: "재고 부족: [품목명] [부족량]" 또는 "BOM 재료 없음" 등
- RPC RAISE EXCEPTION 메시지에서 한국어 부분 파싱하여 표시
- "조립 실행" 버튼은 에러 후 다시 활성화 — 사용자가 수량 조정 후 즉시 재시도 가능

## 인터랙션 패턴

### 라인 입력 (PO, SO, 조립, 이동 공통)
- 인라인 테이블 편집 (useFieldArray)
- 각 행: 품목 드롭다운(검색 가능) + 수량 + 단가 + 금액(자동계산)
- "+ 행 추가" 버튼으로 행 추가
- 각 행 우측 삭제 버튼
- 엑셀과 유사한 UX

### 검색/필터 (모든 목록 화면 공통)
- 상단 검색바: 코드/이름 통합 검색 (debounce 300ms)
- 필터 드롭다운: 상태, 카테고리, 기간 등 (화면별 다름)
- "비활성 포함" 토글 (기본: 숨김)

### 날짜 입력
- 기본값: 오늘 날짜 (자동 설정)
- 과거 날짜 입력 허용 (소급 입력 일반적)
- shadcn Calendar 컴포넌트 사용

### 소프트 삭제 표시
- 목록: 기본 숨김, "비활성 포함" 토글로 표시
- 비활성 항목: 행 배경 회색 + "(비활성)" 뱃지
- 이력 화면: 참조된 비활성 항목은 항상 표시 + "(비활성)" 뱃지

- 모바일 대응 4개 화면만 메뉴에 표시 (대시보드, 재고 현황, 입고 처리, 품목 조회)

- ARIA: shadcn 컴포넌트 기본 제공 활용

## Super Admin vs Company Admin UI 분기

| 기능 | super_admin | company_admin | normal |
|------|-------------|---------------|--------|
| 네비게이션 | 전체 + Admin 섹션 | 전체 (Admin 제외) | 전체 (설정 제외) |
| 회사 관리 | ✅ /admin/companies | ❌ | ❌ |
| 사용자 관리 | ✅ /admin/users (전체) | ✅ /settings/users (자기 회사) | ❌ |
| 회사 설정 | ✅ (모든 회사) | ✅ (자기 회사) | ❌ |
| 원가 재계산 | ✅ | ✅ (확인 대화상자 필수) | ❌ |

### 원가 재계산 확인 절차
```
⚠️ 원가 재계산
이 작업은 전체 재고의 원가를 재계산합니다.
현재 원가 방식: FIFO → 변경: WEIGHTED_AVG
예상 소요시간: 품목 수에 따라 수 초~수 분

[취소] [재계산 실행]
```
실행 중: 프로그레스 바 + "재계산 중... 다른 재고 트랜잭션 입력을 자제해 주세요"

거래처, 품목 일괄 등록 (초기 세팅 시)

```
1. [엑셀 업로드] 버튼 클릭

```

각 화면에서 "샘플 엑셀 다운로드" 링크 제공
